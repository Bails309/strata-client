perf(rdp): drop JPEG, and record where the bandwidth actually goes

JPEG made it worse. Same host, same activity: 7.7 MB as PNG, 10.5 MB as
JPEG at quality 90, on slightly less input. A Windows desktop is flat UI,
which PNG compresses far better than a DCT codec spending coefficients on
areas of identical colour. The assumption that a desktop is mostly
photographic was wrong.

The instrumentation added alongside it is what matters, and it is kept:

    updates 150   megapixels 75.8   megabytes 8.4
    bytes_per_pixel 0.116

At 1920x950 that is about 41 full-screen repaints. Bytes per pixel of
0.116 is roughly 26:1 against raw RGB, so the codec is doing its job.
The engine is not spending too many bytes per pixel, it is sending far
too many pixels.

That rules out the whole class of codec work, JPEG, WebP and EGFX
included, as the first thing to reach for. guacd's advantage here is that
it never sends those pixels: a scroll becomes a copy instruction moving
what the browser already holds. The report now includes full_screens so
the ratio is legible without arithmetic.

force-lossless returns to the ignored list: it only had meaning while
something was encoded lossily.
