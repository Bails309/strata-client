feat(metrics): show what the native engine costs to run

The Sessions blade sized the host on guacd's terms only, so there was
nothing to show for moving the work in-process.

A native session's footprint is known rather than estimated: two
framebuffers at four bytes a pixel, the live one and the previous frame
used to narrow the target's damage rectangles, plus a small fixed
overhead. guacd cannot be costed that way, which is why its figure stays
a blended estimate across RDP, VNC and SSH; a pool instance carries
FreeRDP, cairo surfaces and a worker thread per core whoever is
connected.

Sessions now record which engine serves them, via a flag rather than a
tenth argument to register, and the metrics endpoint reports the native
count alongside the memory each one costs and how many this host would
fit. Both gauges use the same 30 percent reserve and the same CPU bound,
so the two numbers differ only where the engines genuinely differ.

The headroom note is rendered from the ratio rather than asserted, so it
disappears if the advantage ever does.
